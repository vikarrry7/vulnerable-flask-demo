# Экспертная оценка безопасности проекта vulnerable-flask-demo

## Область анализа
Проанализирован исходный код Flask-приложения с помощью SAST-сканера Semgrep.
Код принадлежит авторам проекта, сканирование легально.

## Критические находки

### 1. SQL-инъекция (app.py:17, 20)
**Механизм:** Пользовательский ввод конкатенируется в SQL-запрос через f-string.
**Эксплуатация:** Отправить `username=' OR '1'='1' --` → обход аутентификации.
**Риск:** Полный доступ к БД, утечка данных пользователей.
**Рекомендация:** Использовать параметризованные запросы: `cursor.execute("SELECT * FROM users WHERE username=? AND password=?", (username, password))`.

### 2. Command Injection (app.py:34)
**Механизм:** `os.popen(f"ping -c 1 {host}")` — host из GET-параметра.
**Эксплуатация:** `?host=127.0.0.1; cat /etc/passwd` → чтение файлов.
**Риск:** Удалённое выполнение команд (RCE), компрометация сервера.
**Рекомендация:** Использовать `subprocess.run(["ping", "-c", "1", host], shell=False)` + валидация host.

### 3. Небезопасная десериализация (app.py:27)
**Механизм:** `pickle.loads(request.get_data())` — выполнение произвольного кода.
**Эксплуатация:** Отправить сериализованный payload → RCE.
**Риск:** Полный контроль над сервером.
**Рекомендация:** Заменить на `json.loads`, либо использовать `defusedxml`/`restricted pickle`.

## Средние находки

### 4. Hardcoded secrets (app.py:9-10)
SECRET_KEY и DB_PASSWORD в открытом виде в коде.
**Рекомендация:** Переменные окружения (.env, .gitignore), secrets manager.

### 5. Debug=True (app.py:39)
**Риск:** Раскрытие stack trace, интерактивный debugger (Werkzeug console).
**Рекомендация:** `app.run(debug=False)` в production.

## Низкие находки

### 6. Top-level app.run() (app.py:34)
**Рекомендация:** Обернуть в `if __name__ == "__main__":`.

## Рекомендации общего характера
1. Внедрить SAST в CI/CD (Semgrep через GitHub Actions).
2. Добавить Dependabot для отслеживания уязвимостей в зависимостях.
3. Провести code review с акцентом на OWASP Top 10.
4. Настроить pre-commit hooks с Semgrep.

## Правовое соответствие
- Сканирование выполнено только на собственном коде.
- GitHub Bug Bounty Rules не нарушены (сетевые сканеры не применялись к инфраструктуре GitHub).
- УК РФ ст. 272 не нарушена.
